# Backend working rules

Keep synthetic document data private and model tools read/propose only. `api.py` is the console/module/HTTP entry point; `runtime.py`, `native.py`, `agent.py`, `evidence.py` own native execution and original HTTP/SDK/run evidence. `store.py` and `contracts.py` own exact source revision/protection and human decisions. `datasets.py`, data/manifest.json, fixtures/base.json and scripts/generate_data.py own twelve deterministic versioned cases.

Never patch vendor source/caches or add global clients. Keep the version-guarded async client accessor seam, JSON completion before tool dispatch, true async tools, current-run source bindings and pre-publication cancellation/deadline guards. Clients belong to the API lifespan, checkpoints to a run. Preserve actual committed effects and exact pending recovery after failure; never call that a new effect. Thread/run provenance must not cross attribution boundaries. Human actors are local labels, not authenticated identities.

Preserve legacy_unknown metadata without inventing dates/model history. Seeded human_import decisions need coherent UTC timestamps, actors, source revisions and committed text. Do not feed manifest focus/expected outcomes to the model. Initialization is exclusive/private; never reset another destination or unlink the persistent lock inode. Include data in wheel and sdist. Verify deterministic generation, relevant tests, installed console/module/API from both fresh locked distributions, and the complete frontend archive before delivery. Offline controlled SDK/HTTP/UI results are not live Claude proof. The new Firedrill release, live provider access and publication/license remain external gates.
