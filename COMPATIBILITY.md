# Exercised native runtime and document state

Python 3.12, LangChain **1.4.6**, langchain-core **1.6.10**, langchain-anthropic **1.7.6**, Anthropic **1.14.0**, HTTPX2 **2.13.1**, LangGraph **1.2.15**, LangSmith **0.14.9**, Pydantic **2.14.1**, CopilotKit **0.1.96**, ag-ui-langgraph **0.0.47**. The frontend pins CopilotKit **1.79.0**, AG-UI client **1.0.2**, Next **16.4.1**, React **19.2.2** and Playwright **1.64.1**. Lockfiles qualify the full dependency graphs. Backend TestClient uses HTTPX; the native Anthropic SDK uses HTTPX2 and refuses HTTPX clients.

The original real ChatAnthropic agent dispatched a proposal under max_tokens and then failed on a second controlled 503. The normal path now disables provider streaming, checks original JSON Messages completion before SDK normalization/tool dispatch, and requires end_turn before final AG-UI success. tool_use requires exactly one valid server-owned tool, unique call ID and strict extra-forbid arguments. Unknown/parallel/replayed tools, absent/unfinished/refused completion, unsupported thinking/media blocks, empty final text, malformed JSON and oversized evidence fail. SDK message metadata/tool calls are checked against original HTTP. See the [official Claude stop reason contract](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons). JSON Messages is qualified; provider SSE, server tools and other transports are not. AG-UI events still stream over the UI bridge.

The integration has no public client constructor argument at this version. A version-guarded ChatAnthropic subclass overrides only its two client accessors, retains native formatting/parsing/tool execution and supplies an explicitly owned AsyncAnthropic/HTTPX2 client. No vendor cache/source or process-global client is modified. Clients belong to the API application lifespan and close at shutdown/startup failure, including cancellation of an active request. Per-run checkpoint threads are cleared on success/failure; conversation history is supplied by the client. Chat runs serialize per runtime, and a concurrent run fails before a second model call. A repeated thread/run ID cannot execute again over its existing durable receipt. Use a new run after inspecting failed/uncertain state.

Bounds: eight model calls/prepared HTTP attempts, 24 tool invocations, one tool per response, 4096 output tokens, zero retries, phase/connect limits 30/five seconds, maximum overall run 120 seconds, chat input 100000 UTF-8 bytes. Tracing is disabled through a scoped LangSmith context. Request bytes are checked before dispatch; response evidence is capped at 1 MiB after buffering, not a compressed-wire or memory bound. Actual original JSON/unknown fields, IDs/status/finish, failures and missing/partial/invalid/zero usage remain distinct from SDK defaults; totals require the complete four-counter Anthropic input/output/cache observation. Cost stays unknown. HTTPX errors may wrap a protocol rejection as a connection error; original rejection remains in the receipt.

True async model tools avoid detached write threads. Proposals require an exact current-run read of the target section; original text/revision/protected flag are compared under the shared state lock. Active/deadline/cancellation guards run before work and immediately before atomic replace; a deadline after temp flush prevents a late publication. Tools cannot approve or apply text. Identical pending source/replacement/reason proposals recover without writing another row or claiming a new effect. Failed commit acknowledgement retains the actual created proposal; a completed write cannot be rolled back by later cancellation. Model/native evidence is not proof of semantic editing quality.

Document/proposal schemas reject extra fields, bool/float/string/unsafe revisions, duplicate identities, broken references and oversized state/text. Decision HTTP is strict and requires a named actor; there is no identity authentication. Approval rechecks original section text/revision and protection, preserving other sections/documents. Mutations coordinate through persistent POSIX advisory locks across instances/processes; never unlink the lock inode. Unique private 0600 temp files are flushed/fsynced then atomically replaced, with only owned temp cleanup. Thread/OS lock waits are bounded. Outside file editors do not participate in this ownership. Windows file locking/signals are unqualified.

Private schema-1 .review-runs receipts bind task/instruction hashes and initial/final state, original provider observations, normalized SDK messages, tools and actual created proposal IDs. Final snapshots include operator changes but do not attribute those text edits to the model. A recording fault stops subsequent work; final persistence failure may leave the last file running or an initial file empty, while the exception carries in-memory failed evidence. No blind mutation retry follows uncertain publication.

Eighty-eight backend checks include actual native HTTP, real AG-UI FastAPI exchanges, original completion/usage/failure, recording faults, deadline/cancel/shutdown, replaced source, uncertain commit recovery and concurrent instance/process updates. Two of six production Chromium flows use the actual CopilotKit → AG-UI → native LangChain/Anthropic HTTP → source-read/proposal path: named operator approval only, outage/unfinished failure and recovery, and late selected-document reads/API reload recovery. The first browser run exposed early submission before agent discovery and console-only failures; both are fixed. Markdown source HTML is sanitized before trusted math rendering, with URL hardening and matching KaTeX 0.18.2 CSS; a controlled script/javascript-link response is verified inert. Screenshot inspection confirms the resulting approval state. These are controlled offline SDK/UI results, not live Claude calls.

`synthetic-document-review` v1 contains twelve deterministic hash-bound cases/four profiles, with twenty documents/one hundred sections/thirty human proposals in busy (twelve approved, eight rejected, ten pending). Exact UTC dates/actors, consumed section revisions and latest approved text are checked without inventing legacy provenance or provider trials. Model effect attribution includes exact thread/run, not run name alone; an actual nested pair of native runtimes tests same-named cross-thread attribution. Noncontiguous IDs choose a real library entry, busy queues are searchable, and stale/revision-exhausted approval is unavailable while explicit rejection stays possible. Three additional seeded UI flows cover busy isolated approval, stale rejection and noncontiguous selection.

Manifest hash/schema/identity/population and confined path checks run before private exclusive initialization; existing files/symlinks cannot be reset. Data bundles in backend wheel/sdist. Fresh locked installed console/module CLI list and privately initialize all twelve cases outside checkout and exercise human approval/rejection/pending recovery, safe revisions and model-free API construction. Backend sdist independently regenerates hashes; a complete workspace source archive independently npm-ci/typechecks/production-builds the frontend. The distribution gate is separate from native editing quality. See PLAN.md. Live semantic judgment, the new Firedrill release/persisted cases, publication and licensing remain external gates.
